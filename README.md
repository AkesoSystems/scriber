# УЗД-протокол — МВП

Диктування протоколу УЗД голосом → Claude (ваша підписка Max, без API-кредитів) структурує текст → лікар редагує → експорт у Word/PDF.

## Як це працює

1. **Розпізнавання мовлення** — браузер записує аудіо (`MediaRecorder`), бекенд `POST /api/transcribe` шле його в **Whisper large-v3 через Groq API** (мова uk, словник УЗД-термінів). Точно ловить швидку мову й медтерміни; працює в Chrome, Safari та Edge (зокрема на iPhone). Потрібен `GROQ_API_KEY`.
2. **Структурування** — протокол формує LLM. Пріоритет провайдера: **AWS Bedrock** (Converse API, увімкнено `AWS_REGION`+креди; модель `BEDROCK_MODEL`, за замовч. `us.amazon.nova-pro-v1:0`; оплата AWS-кредитами) → **Anthropic API** (`ANTHROPIC_API_KEY`, Claude Opus 4.8) → резерв `claude -p` на підписці **Claude Max**. Без лімітів підписки.

   > Claude Opus 4.8 на Bedrock наразі заблоковано на рівні акаунта (не self-serve) — тому дефолт `BEDROCK_MODEL` = Amazon Nova Pro (доступна на кредитах одразу, якість для структурування протоколу відмінна). Коли Claude розблокують — змінити `BEDROCK_MODEL` на `anthropic.claude-opus-4-8` (код той самий, Converse).
3. **Редагування** — contenteditable-документ у браузері.
4. **Експорт** — .doc (Word відкриває нативно) або PDF через системний друк ("Зберегти як PDF").

## Запуск локально

```bash
# 1. Node.js 18+ має бути встановлений
cd uzd-mvp
npm install

# 2. Встановити Claude Code і залогінитись підпискою Max (один раз)
npm install -g @anthropic-ai/claude-code
claude            # у діалозі логіну обрати вхід через Claude account (Max), НЕ API key

# 3. Додати ключ Groq для транскрипції у .env
echo "GROQ_API_KEY=gsk_..." >> .env   # ключ з console.groq.com → API Keys

# 4. Запустити
npm start
# відкрити http://localhost:3000 у Chrome, Safari або Edge
```

Перевірити, що headless-режим працює, можна так:
```bash
echo "привіт" | claude -p --output-format text
```

## Деплой на сабдомен (uzd.вашдомен.com)

1. VPS з Ubuntu, Node 18+, той самий `npm i -g @anthropic-ai/claude-code`.
2. Логін Claude Code на сервері: запустити `claude`, він дасть URL для OAuth — відкрити його у своєму браузері, вставити код назад. Креденшіали збережуться в `~/.claude/`.
3. Запуск через pm2: `pm2 start server.js --name uzd`.
4. Nginx reverse proxy на порт 3000 + сертифікат (certbot). **HTTPS обов'язковий** — без нього браузер не дасть доступ до мікрофона.
5. Поставити хоча б Basic Auth у Nginx, щоб сторінка не була публічною.
6. **`GROQ_API_KEY`** — задати в середовищі процесу (Coolify → Environment Variables, або `.env`/pm2 ecosystem). Без нього транскрипція повертає помилку.

> Деплой через **Coolify**: репозиторій підключено; `git push` у `main` запускає перебудову Docker-образу. `GROQ_API_KEY` додається в Coolify → Environment Variables (секрет), потім Redeploy.

## Важливі обмеження

- **Ліміти Max** — підписка має ліміт повідомлень на 5-годинне вікно. Для одного-кількох лікарів на МВП вистачає; на потік пацієнтів у кількох кабінетах — уже ні, тоді доведеться переходити на API.
- **Точність розпізнавання** — Whisper large-v3 значно точніший за Web Speech на українській і медтермінах, але сумнівні місця Claude все одно позначає `[?]`; лікар зобовʼязаний вичитати протокол перед збереженням.
- **Транскрипція зʼявляється після «Зупинити запис»** — Whisper розпізнає весь запис цілісно (живого тексту під час диктовки немає), текст приходить через кілька секунд після зупинки.
- **`GROQ_API_KEY`** — на проді задається в Coolify → Environment Variables (не в git). Безкоштовний тір Groq покриває тест; платний — центи за обстеження.
- **Claude не вигадує даних** — якщо параметр не продиктовано, у протоколі його не буде (промпт це жорстко забороняє).
- **Персональні дані** — у диктовці краще не називати ПІБ пацієнта: аудіо проходить через Groq (Whisper) і текст через Claude. ПІБ можна вписати вручну вже в редакторі перед експортом.

## Як додати нового тестувальника

Кожен лікар-тестувальник = окремий логін Basic Auth (`test`, `test2`, … — саме за ним аналітика
розрізняє «хто заходив»). Щоб завести нового, пройди ВСІ кроки — особливо крок 3 (протокол),
бо без нього лікар отримає стандартний шаблон замість свого.

1. **Акаунт у nginx** (на VPS, той самий файл, де решта логінів):
   ```bash
   htpasswd -B /etc/nginx/.htpasswd test7      # введе пароль; reload nginx не потрібен
   ```

2. **Нік** — у `server.js` → `NICKNAMES_BY_USER` додай `test7: "Імʼя Лікаря"`.
   (Імена тестерів ведемо в таблиці `leads-outreach` → вкладка `clients-testers`, колонка «Нік/Пароль».)

3. **⚠️ Протокол (НЕ ЗАБУТИ).** Признач лікарю правильний тип протоколу — інакше він отримає
   `default` (стандарт черевної порожнини), що для нього може бути не те:
   - **Тип уже існує** (черево+щитоподібна, дитяча ехо, вет ZOOLUX, формат Ольги тощо) →
     додай у `PROMPTS_BY_USER` рядок `test7: "ключ_шаблону"` (ключі дивись у реєстрі `TEMPLATES`).
   - **Новий тип протоколу** → спершу 1) напиши константу-промпт `const SYSTEM_PROMPT_TESTER7 = ...`,
     2) зареєструй її в `TEMPLATES` (`ключ: { label: "Людська назва", prompt: SYSTEM_PROMPT_TESTER7 }`),
     3) і лише тоді признач `test7: "ключ"` у `PROMPTS_BY_USER`.
   - **Стандартний (черевна порожнина)** → нічого не додавай, `default` застосується сам.

4. **Деплой** — `git push` у `main`, Coolify перебудує. Пароль акаунта повідом лікарю.

> Випадайку шаблонів у нейтральному QA-акаунті `demo` чіпати НЕ треба — вона будується
> автоматично з `TEMPLATES`/`PROMPTS_BY_USER`, тож новий лікар одразу зʼявиться біля свого шаблону.
